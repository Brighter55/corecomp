# Run the local app

Start every piece of the local dev environment and confirm each one is up before reporting.

## Layout (use absolute paths — work from any cwd)

- Project root: `C:\Users\meanp\Desktop\VSCODE\corecomp`
- Backend: `server/` — Django 5.2 + DRF, managed with pipenv (`Pipfile`)
- Frontend: `client/` — React 19 + Vite (`npm run dev`)
- Redis: Docker container `redis:7-alpine` (no native Windows build — this is the only service that runs in Docker)
- Postgres: native Windows service `postgresql-x64-17` on localhost:5432

## Data mode: local dev runs on LIVE data

`server/.env` sets **`MOCK=False`**, so the backend calls WiseSheets directly for every data endpoint. That key is **the same one production uses**, on a shared free tier of **5,000 requests/month**. Browsing the local app spends real budget — say so when you report, rather than letting it be discovered later.

Rough cost per cold symbol (repeat views inside the cache TTL are free):

| Page | Upstream requests |
|---|---|
| `/dip` (one symbol) | 1 |
| `/overview` (one symbol) | ~6 |

**Switching to mock** (offline, no quota): set `MOCK=True` in `server/.env`, then `pipenv run python corecomp/manage.py clear_cache`, then restart. Three things make this fiddly:

- The flush is **mandatory in both directions**. Cache keys are not mode-namespaced, so without it the previous mode's bytes are served for up to 7 days. `/dip`'s key is the one exception — it is mode-prefixed.
- `MOCK` is read at **import time** (`services/__init__.py`), so the backend must be restarted, not just reloaded.
- Mock mode needs the fixtures in `pages/statement_samples/`. They are **gitignored** and generated by `generate_statement_samples` — see Troubleshooting.

## Steps

1. **Redis** — run `docker compose up -d` in `server/`. Idempotent: starts the container if missing, no-ops if running. If Docker Desktop isn't running, ask the user to start it and retry.

2. **Postgres** — verify the `postgresql-x64-17` service is running (`Get-Service postgresql-x64-17`). If stopped, start it.

3. **Check the ports before starting anything** — see Troubleshooting. On this machine the Vite server in particular is often already running, and starting a second one is worse than reporting the first.

4. **Backend** — from `server/`, in background:
   ```
   pipenv run python corecomp/manage.py runserver
   ```
   Runs on :8000. Confirm readiness by **polling the port**, not by grepping the banner (the startup text varies; the Autoreloader prints `Watching for file changes with StatReloader` rather than the classic banner):
   ```
   until curl -s -o /dev/null http://localhost:8000/admin/login/; do sleep 0.5; done
   ```

5. **Frontend** — from `client/`, in background:
   ```
   npm run dev
   ```
   Wait for `Local: http://localhost:5173`.

6. **Verify** — confirm both ports answer (HTTP 200), then report:
   - Backend: http://localhost:8000 (Django; `http://localhost:8000/admin/login/` as a free health check)
   - Frontend: http://localhost:5173 (Vite; talks to the backend via `VITE_BACKEND_BASE_URL` from `client/.env`, CORS already configured)

   A free way to prove a data route is wired up without spending quota: `POST` to it with no `X-Anonymous-Session` header. A **403** means the route exists and its permission is active; a **404** means it isn't registered.

## Troubleshooting

- **Port 8000 or 5173 already in use** — the app is probably already running. Confirm it's *this* project before moving on, e.g. `Get-CimInstance Win32_Process -Filter "ProcessId = <pid>"` and check the command line points at `corecomp/client`. Report it rather than starting a duplicate.
- **Backend 500s on data endpoints** — Redis is usually the culprit: check `docker compose ps` in `server/`.
- **Symbol search returns nothing** — the `Symbol` table is empty. Seed it: `pipenv run python corecomp/manage.py import_symbol_model --source sec`. Use `--source sec`: it makes **one** free SEC EDGAR call, whereas the default `--source wisesheets` paginates `/companies/` and can spend ~1,000 requests of the shared monthly quota.
- **Data endpoints 500 under `MOCK=True`** — the gitignored fixtures are missing. Regenerate: `pipenv run python corecomp/manage.py generate_statement_samples --symbol IBM`. It only writes the 8 files it knows about and never deletes others.
- **Stale data after flipping `MOCK`** — expected; see Data mode above. Note `clear_cache` is a `FLUSHALL`, so it also wipes `anon_quota:*` and resets local quota counters.
- **Quota looks exhausted locally** — the anonymous allowance is 5 unique symbols per 30 days, tracked per `X-Anonymous-Session`. A browser gets its own id from localStorage, so curl checks with a made-up session header don't consume the browser's allowance (and vice versa). To reset, delete the `anon_quota:*` keys or run `clear_cache`.
- **Postgres auth errors** — credentials in `server/.env` must match the native install (local dev only: user/pass `corecomp`/`corecomp`, db `corecomp`).
- **Sample data missing** — fixtures live in `server/corecomp/pages/statement_samples/` and resolve relative to `services.py` (CWD-independent). Only relevant under `MOCK=True`.
